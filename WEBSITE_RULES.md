# WEBSITE_RULES.md

# VKD Apps Engineering Rules

Version 1.0

---

# Production Website

This repository powers the LIVE production website.

Website

https://vkdapps.com

Hosting

Cloudflare Pages

Repository

GitHub

Every change made in this repository can affect the live website.

Treat every modification as production code.

---

# Rule 1

Never regenerate the entire website.

Never replace the project with a new template.

Never rebuild from scratch.

Always improve the existing project.

---

# Rule 2

Never change the repository structure.

Never rename folders.

Never rename assets.

Never move directories.

Never create unnecessary folders.

Only create new files when absolutely required.

---

# Rule 3

Never modify

Git configuration

Cloudflare configuration

Deployment configuration

Repository settings

Branch structure

Build configuration

Package manager configuration

unless explicitly requested.

---

# Rule 4

Never remove existing working functionality.

If replacing a section,

replace it with something objectively better.

Never delete sections without replacement.

---

# Rule 5

Never remove products.

The website only contains

PickSpin

BrainBoost

Rent Agreement Maker

FlowCare

Do not invent additional products.

Do not rename products.

Do not remove products.

---

# Rule 6

Never replace real screenshots with placeholders.

Real screenshots always have higher priority.

If screenshots are missing,

create placeholders with comments.

Never delete existing screenshots.

---

# Rule 7

Never invent

Customers

Testimonials

Statistics

Awards

Certifications

Press mentions

Downloads

Revenue

Employees

Partners

Investors

Reviews

Everything displayed must be truthful.

---

# Rule 8

Never use

Lorem Ipsum

Placeholder marketing copy

Fake business language

AI clichés

Buzzwords

Generic startup phrases

Meaningless paragraphs

Every sentence should communicate real value.

---

# Rule 9

Every section must answer

Why does this exist?

If the section adds no value,

remove it.

If two sections say the same thing,

merge them.

---

# Rule 10

Whitespace must be intentional.

Never create empty sections.

Never leave huge gaps.

Never increase spacing without purpose.

Every pixel should have a reason.

---

# Rule 11

Homepage should prioritize

Products

Services

Trust

Contact

Do not push products below unnecessary sections.

Products are the strongest proof of engineering quality.

---

# Rule 12

Never create long scrolling pages without purpose.

Prefer fewer sections with higher quality.

Quality over quantity.

---

# Rule 13

Navigation should always remain simple.

Maximum top-level navigation items

Home

Products

Services

About

Contact

No unnecessary navigation items.

---

# Rule 14

Every page must contain

Clear heading

Clear purpose

Call to action

Good spacing

Responsive layout

Accessible markup

SEO metadata

---

# Rule 15

Every image must have a purpose.

Prefer

Real screenshots

Product mockups

SVG illustrations

Custom graphics

Never use

Fake offices

Fake developers

Stock business meetings

Random technology photos

AI-generated people

---

# Rule 16

Animations must improve usability.

Never animate everything.

Never create distracting motion.

Use animation only to

Guide attention

Provide feedback

Improve navigation

Support storytelling

Respect prefers-reduced-motion.

---

# Rule 17

Never decrease performance.

Target

Lighthouse Performance

98+

Accessibility

100

SEO

100

Best Practices

100

Do not introduce unnecessary JavaScript.

Do not introduce large dependencies.

---

# Rule 18

Accessibility is mandatory.

Keyboard navigation.

ARIA labels.

Alt text.

Semantic HTML.

Visible focus.

Readable contrast.

Reduced motion.

---

# Rule 19

SEO is mandatory.

Every page requires

Unique title

Unique description

Canonical

Open Graph

Twitter Cards

Structured Data

JSON-LD

Proper heading hierarchy

---

# Rule 20

Always reuse existing CSS.

Avoid duplicate styles.

Avoid inline styles.

Avoid duplicated components.

Keep code modular.

---

# Rule 21

Do not duplicate HTML.

If a reusable component exists,

reuse it.

---

# Rule 22

Every new component must work on

Desktop

Laptop

Tablet

Android

iPhone

Landscape

Portrait

---

# Rule 23

Never modify unrelated files.

If asked to improve

Homepage

Only modify homepage-related files.

Do not modify

Products

Services

Footer

unless required.

---

# Rule 24

Always review your own work.

Before finishing

check

Broken links

Broken images

Console errors

Accessibility

Responsiveness

Spacing

Typography

Animation

Performance

SEO

Fix issues before returning.

---

# Rule 25

After implementation

become a Senior Code Reviewer.

Review everything.

Find

Visual inconsistencies

Duplicate CSS

Dead code

Unused classes

Broken layouts

Poor spacing

Weak typography

Accessibility issues

Performance issues

Fix every issue.

---

# Rule 26

Then become Creative Director.

Review again.

Ask

Does this still feel AI generated?

If yes,

continue improving.

Repeat until it feels handcrafted.

---

# Rule 27

Every deployment must leave the website in a deployable state.

Never leave

Broken HTML

Broken CSS

Broken JavaScript

Broken navigation

Broken assets

Broken links

---

# Rule 28

Every Git commit should represent one logical improvement.

Examples

Improve Hero

Improve Products

Improve Services

Improve Footer

Improve SEO

Never combine unrelated work into one commit.

---

# Rule 29

Before writing code,

understand the existing implementation.

Read existing HTML.

Read CSS.

Read JavaScript.

Understand architecture first.

Never assume.

---

# Rule 30

When uncertain,

ask.

Do not guess.

Do not invent.

Do not hallucinate.

Request clarification before making destructive changes.

---

# Final Engineering Principle

This website represents VKD Apps.

Every change should increase

Trust

Professionalism

Performance

Maintainability

Readability

User Experience

Conversion

Engineering Quality

If a change does not improve at least one of these,

do not implement it.

---

# Golden Rule

Build software the way VKD Apps builds software.

Thoughtfully.

Incrementally.

Professionally.

Never sacrifice quality for speed.

Every deployment should make the website better than the previous one.
